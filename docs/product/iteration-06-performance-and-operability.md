# 迭代 06 - 性能、稳定性与可运维性

## 目标

把当前桌面原型从“功能能跑”推进到“长时间运行更稳定、启动更快、状态更透明”的阶段，为后续商业化交付打底。

## 本次迭代内容

### 1. 本地行情缓存

- 为全市场快照和个股日线数据增加本地磁盘缓存。
- 快照缓存用于降低重复请求频率，减少盘中连续刷新时的远程压力。
- 日线缓存用于降低个股历史数据反复拉取造成的卡顿。
- 当远程接口失败时，允许回退到过期但可用的本地缓存，避免界面空白。

### 2. 后台任务与防卡顿

- 全市场筛选、本地扫描、推荐池生成、参数优化统一改成后台任务。
- 加入任务去重，避免重复点击或自动刷新导致同类任务并发堆积。
- 启动时先拉起界面，再异步加载市场数据和本地扫描结果，降低“假死感”。

### 3. 运行状态与系统日志

- 在“交易执行”页增加运行状态 / 系统日志面板。
- 展示活跃任务数、缓存文件数、缓存体积和最近日志条数。
- 记录任务开始、任务完成、任务失败、缓存回退等关键信息，便于排查问题。

### 4. 商业化底座增强

- 继续坚持“研究、筛选、风控、人工确认执行”的产品边界。
- 不承诺收益，不绕过券商安全校验，不实现黑盒账户接管。
- 为后续多数据源、多授权版本、多团队协作做准备。

## 用户价值

- 启动更快，界面更早可见。
- 盘中连续刷新时更不容易卡住。
- 远程行情接口波动时，产品仍能利用缓存保持可用。
- 出问题时用户可以在界面里直接看到任务和日志，而不是只能猜测程序是否卡死。

## 实现位置

- `quant_hunter/market_feed.py`
  - 新增 `LocalMarketCache`
  - 快照 / 日线缓存读写
  - 远程失败时回退到缓存
- `app_qt.py`
  - 后台任务统一调度
  - 任务去重
  - 运行状态 / 系统日志面板
  - 关键任务状态日志接入

## 验收标准

- 应用启动时不再阻塞在全市场筛选。
- 同类后台任务重复触发时不会无限堆积。
- 界面可以显示缓存规模和任务日志。
- 远程行情失败时，若本地存在缓存，产品仍可加载数据。
- 自动化测试通过，桌面端启动验证通过。

## 后续建议

- 把大表格逐步迁移到 `QAbstractTableModel`，继续降低大数据量时的内存和绘制压力。
- 把运行日志导出到本地文件，形成可审计的运维日志。
- 为每个关键任务补充取消、超时和重试控制。
- 引入更细粒度的性能指标，例如刷新耗时、缓存命中率、失败率。
