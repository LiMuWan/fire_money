# 迭代 83：消息驱动工作流验收收口

## 目标

- 把股票消息能力从“能展示”推进到“能带着用户进入交易工作流”。
- 补齐产品内的验收口径，减少后续继续迭代时的上下文丢失。

## 当前完成

- 消息源接入
  - 本地 CSV
  - 示例消息源
  - 巨潮公告适配器
  - 公告 + 线索混排

- 消息处理
  - `A/B/C` 可信度分层
  - 巨潮公告标题压缩
  - 同日配套公告归并
  - 公告类型到交易语言翻译
  - 公告与线索统一排序

- 页面展示
  - 首页消息催化卡
  - 首页摘要卡消息分层
  - 推荐焦点消息复核区
  - 消息原文按钮
  - 消息详情弹窗
  - `消息驱动` 焦点徽标
  - 榜单卡/摘要卡上的消息驱动 badge

- 工作流联动
  - 从消息详情跳到推荐页
  - 从消息详情跳到复盘页
  - 从消息详情跳到交易页
  - 跳转后同步当前焦点股票
  - 焦点条保留 `消息驱动` 来源感
  - 短时提示 `刚由消息定位`

## 首页验收点

- 首页消息催化卡应显示：
  - 消息分层
  - 当前焦点股票
  - 建议动作
  - 最近消息
  - 炒作逻辑

- 首页摘要卡中的“消息分层”卡应在消息驱动时显示 badge。

- 首页消息按钮应满足：
  - 有原文时可打开
  - 无原文时给出明确提示
  - 文案会随 `已公告 / 媒体催化 / 传闻线索` 变化

## 推荐页验收点

- 推荐焦点区应显示：
  - 焦点消息详情按钮
  - 焦点消息原文按钮
  - `消息驱动` 来源徽标

- 推荐摘要卡中的“为什么看它”应在消息驱动时显示 badge。

## 详情弹窗验收点

- 消息详情弹窗应显示：
  - 分层
  - 来源
  - 时间
  - 标题
  - 摘要
  - 原文可用性
  - 建议动作

- 若消息为归并公告，应显示“配套公告”列表。

- 弹窗内应支持：
  - 查看原文
  - 查看推荐
  - 查看复盘
  - 去交易页

## 交易工作流验收点

- 从消息跳到交易页后：
  - 当前股票应被同步为焦点
  - 委托焦点应带 `消息驱动`
  - 状态 banner 应带 `消息驱动`

- 从消息跳到复盘页后：
  - 复盘焦点 banner 应带 `消息驱动`

## 当前已覆盖测试

- 纯 helper 级测试
- provider 级测试
- 消息分层与 tooltip 测试
- 消息详情与建议动作测试
- 跳转与焦点联动测试
- Qt 窗口级 smoke 测试

## 已知边界

- 当前窗口级 smoke 更偏“结构和链路可用”，还不是桌面级 GUI 自动点击。
- 巨潮公告适配器基于官网公开链路，适合当前版本使用，但后续如官网字段变动仍需跟进。
- 媒体源目前主要依赖示例或本地 CSV，正式财经媒体源仍建议在拿到稳定授权或接口后接入。

## 下一步建议

- 若继续做功能，优先做真实媒体源接入。
- 若进入交付阶段，优先安排一次人工验收，把首页、推荐、复盘、交易四条消息链实际点一遍。
- 人工验收可直接参考 [迭代 84：消息工作流人工验收清单](C:/Users/18335/Documents/New%20project/docs/product/iteration-84-message-workflow-manual-checklist.md)。
