# Quant Hunter 项目适配版产品优化与开发方案

## 1. 项目现状判断

当前项目不是从零开始的炒股产品，而是已经具备明确定位的桌面量化交易工作台：

- 前端壳层：`PySide6` 桌面工作台，已拆分多个 workspace。
- 核心流程：`扫描 -> 推荐 -> 打板 -> 明细 -> 交易 -> 复盘`。
- 算法底座：已有 `scanner.py`、`recommend.py`、`decision.py`、`backtest.py`、`optimizer.py`。
- 执行桥接：已有 `broker.py`、`sdk_bridge.py`，支持半自动和 SDK 两套链路。
- 商业化准备：已有授权、状态、工作台拆分、报告导出和运行时诊断方向。

这说明项目最应该做的不是“再做一个新产品”，而是把现有能力升级成更强的闭环产品。

一句话定位建议：

`Quant Hunter = 面向 A 股活跃交易者的可解释、可执行、可复盘的桌面决策工作台`

## 2. 现有能力与代码映射

### 2.1 工作台层

- 总览：`build_overview_workspace`
- 扫描：`_build_scanner_tab`
- 推荐：`build_recommend_workspace`
- 打板：`build_board_workspace`
- 明细：`build_detail_workspace`
- 交易：`build_broker_workspace`
- 配置：`build_config_workspace`

### 2.2 决策链路层

- 信号扫描：`quant_hunter/scanner.py`
- 推荐池构建：`quant_hunter/recommend.py`
- 仓位与动作决策：`quant_hunter/decision.py`
- 回测引擎：`quant_hunter/backtest.py`
- 参数优化：`quant_hunter/optimizer.py`
- 交易意图与审查：`quant_hunter/broker.py`

### 2.3 数据结构层

- 核心推荐对象：`RecommendationRow`
- 扫描结果对象：`ScanRow`
- 个股分析对象：`DailyAnalysis`
- 交易执行对象：`OrderIntent`

当前 `RecommendationRow` 已经具备五大战法得分、主策略、题材、买卖点和风险线，基础非常好，说明你们已经具备“战法化产品”的雏形。

## 3. 当前最强优势

- 已经形成完整工作台，而不是单页 demo。
- 五大战法已经写进推荐结构体，不是纯文案概念。
- 推荐池和交易执行已经能联动，不是孤立看盘工具。
- 已经重视复盘、日志、导出、运行状态，这对商业化很重要。
- 保留“人工确认 + 半自动执行”的合规边界，方向正确。

## 4. 当前最大短板

### 4.1 首页强，但交易前判断还不够硬

现在总览、推荐、交易页都已有内容，但用户在真正下单前，缺一层更清晰的“是否值得出手”总判断。

### 4.2 推荐逻辑有了，个性化还不够

当前推荐体系更像统一模型，对不同风格用户还不够细。短线追强、低吸修复、趋势波段用户需要不同权重。

### 4.3 执行链路有了，闭环反馈还不够深

目前有执行状态、复盘文本，但还没有把“执行结果反哺模型参数”做成真正的数据闭环。

### 4.4 风控更多在交易页，缺盘前前置风险层

很多风险应该在推荐阶段就暴露，而不是等到送审或提交时才发现。

## 5. 项目适配版产品升级目标

下一阶段不是继续堆页面，而是把产品升级成 4 个闭环：

1. 市场闭环：识别主线、情绪、题材强弱。
2. 机会闭环：找出值得看、值得买、值得放弃的标的。
3. 执行闭环：把推荐变成审查、委托、结果记录。
4. 进化闭环：让复盘结果进入下一轮推荐与策略优化。

## 6. 按模块给出的优化方案

### 6.1 总览页

目标：让用户 30 秒内知道今天能不能打、该打什么、风险在哪。

保留：

- 市场驾驶舱
- 盘前优先级卡片
- 龙头池与市场筛选
- 市场状态与自动刷新

新增优化：

- 增加“今日出手等级”：进攻、均衡、防守、观望。
- 增加“主线可信度”：主线是否清晰、是否适合扩仓。
- 增加“推荐池质量条”：强买、观察、风险票占比。
- 增加“市场失败信号”：高开低走、炸板率升高、资金分歧。

算法建议：

- 把 `decision.py` 的 `MarketPulse` 从情绪分扩展为市场状态对象。
- 新增字段建议：`attack_level`、`theme_clarity`、`failure_risk`、`execution_window_score`。

### 6.2 扫描页

目标：从“扫出信号”升级成“扫出可处理机会”。

保留：

- 信号扫描榜
- 回测摘要
- 盘中监控

新增优化：

- 增加扫描结果分桶：可建仓、待确认、仅观察、需放弃。
- 增加信号失效原因字段。
- 增加“入选但不推荐”的反例展示。

算法建议：

- 对 `ScanRow` 增加 `risk_flag`、`invalidate_reason`、`execution_readiness`。
- 扫描结果不要只按分数排序，要按“可执行性优先级”排序。

### 6.3 推荐页

目标：把这里做成全产品最核心的收益引擎。

保留：

- 五大战法
- 推荐池表格
- 执行分层、策略决策、复盘沉淀
- 推荐推送到交易执行

新增优化：

- 增加用户风格模板：追强、低吸、趋势、均衡。
- 增加推荐可信度和推荐时效。
- 增加“为什么不是买入而只是观察”的解释。
- 增加“相似历史案例”摘要。

算法建议：

- `recommend.py` 中当前总分权重可升级成“基础权重 + 用户风格权重 + 市场环境权重”三层结构。
- 为 `RecommendationRow` 增加字段建议：
  - `confidence_score`
  - `execution_readiness`
  - `timeliness_score`
  - `reject_reason`
  - `historical_pattern_tag`

### 6.4 打板页

目标：把打板模式做成高风险高收益专属工作台，而不是普通推荐页的子集。

保留：

- 打板候选
- 回封观察
- 炸板风险

新增优化：

- 增加回封强度评分。
- 增加炸板后是否值得二次观察。
- 增加封单质量、盘口承接、情绪共振摘要。

算法建议：

- `board.py` 增加 `seal_strength`、`reopen_risk`、`rebound_watch_score`。
- 打板策略要和普通趋势策略完全分离止损逻辑。

### 6.5 明细页

目标：让一只股票的结论足够清楚，能支撑最后决策。

保留：

- 决策文本
- 执行文本
- 结论文本

新增优化：

- 增加“三段式结论”：
  - 现在怎么看
  - 为什么这样看
  - 什么时候失效
- 增加策略得分雷达图或简化分布卡。
- 增加题材链路与催化事件时间线。

算法建议：

- 把 `recommend.py` 和 `decision.py` 的解释文本统一为同一模板。
- 避免不同页面对同一只股票说法不一致。

### 6.6 交易页

目标：把交易执行页从“订单提交器”升级成“交易审查中心”。

保留：

- 账户状态
- 订单意图表
- 二次确认
- 结果日志

新增优化：

- 增加交易前检查单：仓位、集中度、市场状态、风险收益比、是否追高。
- 增加“本次委托对组合影响”的预估。
- 增加失败委托自动复审建议。

算法建议：

- 在 `broker.py` 的 readiness score 基础上扩展为多因子执行审查模型。
- 新增结果建议：
  - 允许提交
  - 建议缩量提交
  - 延迟观察
  - 禁止提交

### 6.7 配置页

目标：从参数页升级成策略控制台。

保留：

- 主线前 N
- 总仓位上限
- 候选上限

新增优化：

- 增加风格模板切换。
- 增加风险等级模板。
- 增加盘前、盘中、盘后不同模式。
- 增加回测参数和实时参数分离。

## 7. 最值得优先开发的算法升级

### 7.1 从“统一评分”升级到“场景化评分”

当前模型已经能打分，但下一步重点是让评分更贴近真实交易场景。

建议升级为：

- 基础分：技术、位置、持续性、消息、龙头属性。
- 场景分：市场环境、题材强度、执行窗口、风险回报。
- 用户分：风格偏好、仓位状态、当前持仓暴露。
- 结果分：历史命中、最近失效、相似案例反馈。

### 7.2 从“推荐动作”升级到“动作置信度”

不是只告诉用户 `买入/观察/减仓/离场`，而是同时告诉用户：

- 有多值得做
- 有多容易做
- 做错的主要风险是什么

### 7.3 从“复盘文案”升级到“策略反馈回路”

复盘不是导出一段文字，而是反向影响下一次推荐。

建议沉淀：

- 哪类票更容易送审后失败
- 哪类策略在弱市中误报更高
- 哪类题材隔日持续性最差
- 哪类买点执行后胜率更高

## 8. 建议的数据结构升级方向

优先围绕 `RecommendationRow`、`ScanRow`、`OrderIntent` 做扩展，不要推倒重建。

建议新增的核心字段：

- `confidence_score`
- `execution_readiness`
- `timeliness_score`
- `market_state_tag`
- `risk_flag`
- `invalidate_reason`
- `reject_reason`
- `portfolio_impact_score`
- `review_feedback_tag`

## 9. 推荐的开发优先级

### P0：马上做

- 统一总览、推荐、明细、交易页的结论表达口径。
- 给推荐结果加上置信度、可执行性、失效条件。
- 给交易页补齐交易前检查单和组合影响评估。

### P1：第二阶段

- 做用户风格模板。
- 做推荐池分桶和失败原因分析。
- 做复盘反馈结构化。

### P2：第三阶段

- 做策略自适应权重。
- 做相似案例回放。
- 做更细的团队版权限、日志、协作能力。

## 10. 具体开发切入建议

如果按最稳的方式推进，建议开发顺序如下：

1. 先改模型层和数据结构，让推荐对象更完整。
2. 再改推荐页和明细页，把解释和分层做好。
3. 然后补交易页的审查中心。
4. 最后再让复盘数据反哺推荐算法。

建议优先改动的代码文件：

- `quant_hunter/models.py`
- `quant_hunter/recommend.py`
- `quant_hunter/decision.py`
- `quant_hunter/broker.py`
- `quant_hunter/workspace_builders.py`
- `quant_hunter/ui_refresh.py`

## 11. 这份方案的落地方向

本方案不是替换现有产品，而是帮助现有项目完成三件事：

- 从“能用”升级到“更专业”
- 从“有推荐”升级到“更可信”
- 从“能执行”升级到“能持续进化”

下一步最适合直接进入开发的专题有三个：

1. 推荐池置信度与失效条件体系
2. 交易前审查中心
3. 复盘反馈反哺推荐模型

如果继续推进，建议下一轮直接从第 1 项开始落代码，因为它对总览、推荐、明细、交易四个页面都会立刻产生价值。
