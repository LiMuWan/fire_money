# 迭代 01：最小可用原型

## 1. 迭代目标

做出一个可每天使用的桌面版最小原型，满足以下闭环：

1. 每天根据市场数据和消息生成股票池。
2. 交易建议只从股票池中产生。
3. 对已有持仓给出加仓、减仓、离场建议。
4. 每次运行都输出 Markdown 报告，方便人工审核和复盘。

这个版本不追求“全自动交易”，而是先把研究到执行前确认的链路跑通。

## 2. 目标用户

- 每天盘前会做交易计划的个人投资者
- 有一定交易经验，能理解仓位和止损
- 愿意先接受“AI 建议 + 人工确认”的工作模式

## 3. MVP 范围

### 3.1 必做功能

- 市场情绪面板
- 每日股票池生成
- 股票池内交易建议
- 持仓诊断
- 盘前计划报告导出
- 盘后复盘报告导出

### 3.2 暂不纳入

- 自动实盘下单
- 复杂多账户体系
- 云端协作
- 企业权限系统
- 完整订阅计费

## 4. 业务规则

### 4.1 交易入口规则

- 任何新建仓动作必须来自当日“可交易池”。
- 如果股票不在池中，只允许加入观察，不允许给出建仓建议。

### 4.2 仓位规则

- 市场情绪高：允许 3 到 5 个新仓。
- 市场情绪中：允许 1 到 3 个新仓。
- 市场情绪低：最多 0 到 1 个试错仓。

### 4.3 风险规则

- 单票默认止损 3% 到 6%。
- 单票建议仓位不超过总资金 20%。
- 若市场进入退潮，优先输出减仓与离场建议。

## 5. 用户流程

### 5.1 盘前

- 用户点击刷新。
- 系统更新市场情绪、新闻催化和候选股票。
- 系统生成今日股票池。
- 系统输出盘前计划 Markdown。

### 5.2 盘中

- 用户查看股票池触发情况。
- 系统对满足条件的标的输出 BUILD / ADD / WATCH。
- 系统对持仓输出 HOLD / TRIM / EXIT。

### 5.3 盘后

- 用户生成复盘。
- 系统输出当日命中、错过、风控触发和次日观察名单。

## 6. 指标方案

### 6.1 市场情绪指标

- 涨跌家数比
- 涨停/跌停数量
- 两市成交额与 5 日均值偏离
- 昨日强势股溢价
- 炸板率

输出：

- 市场情绪分
- 市场状态
- 总仓位上限

### 6.2 股票池指标

- 趋势强度：MA5、MA10、MA20、MA60
- 放量程度：量比、成交额变化
- 结构信号：突破、回踩、反包、平台
- 相对强弱：相对指数表现
- 消息催化：新闻标题、公告摘要、政策事件

输出：

- 入池得分
- 入池标签
- 建议动作
- 买点、止损、目标位

### 6.3 持仓建议指标

- 当前盈亏比例
- 是否跌破结构位
- 是否达到分批止盈条件
- 板块热度是否衰减
- 市场情绪是否恶化

输出：

- ADD / HOLD / TRIM / EXIT
- 理由
- 风险说明

## 7. 页面需求

结合你给的截图，MVP 建议采用 4 区结构：

### A 区：市场总览

- 上证、深成、创业板核心指数
- 市场情绪分
- 涨跌分布柱图
- 今日风险级别

### B 区：板块与消息

- 热门题材排行
- 今日催化新闻
- 龙头股摘要

### C 区：每日股票池

- 股票代码
- 股票名称
- 题材
- 总分
- 动作
- 买点
- 止损
- 目标位
- AI 原因

### D 区：持仓动作台

- 当前持仓
- 浮盈浮亏
- 建议动作
- 风险状态
- 人工确认按钮

## 8. 输出文档要求

每次运行至少输出两类 Markdown 文档：

### 8.1 盘前计划

文件建议：

```text
exports/daily_plans/daily_plan_YYYYMMDD.md
```

内容结构：

- 市场情绪摘要
- 今日主线题材
- 每日股票池
- 建仓候选
- 风险提示

### 8.2 盘后复盘

文件建议：

```text
exports/review_reports/end_of_day_review_YYYYMMDD.md
```

内容结构：

- 当日市场回顾
- 股票池表现
- 实际执行记录
- 风控触发情况
- 次日观察名单

## 9. 技术实现方案

## 9.1 数据流

1. 数据采集层读取行情、股票元数据、新闻催化。
2. 市场情绪引擎生成情绪分和仓位上限。
3. 股票池引擎筛选“可交易池”。
4. 决策引擎对股票池和持仓分别输出动作。
5. 报告引擎输出 Markdown 报告。
6. 桌面端展示并等待人工确认。

## 9.2 模块拆分

建议在现有代码上这样落地：

- `quant_hunter/market_feed.py`
  负责指数、涨跌家数、成交额和消息数据标准化。
- `quant_hunter/scanner.py`
  扩展为“每日股票池引擎”。
- `quant_hunter/decision.py`
  增加 BUILD / ADD / TRIM / EXIT 规则。
- `quant_hunter/recommend.py`
  聚合打分并生成 AI 解读。
- `quant_hunter/reports.py`
  输出盘前和盘后 Markdown。
- `app_qt.py`
  新增市场总览、股票池和持仓动作台。

## 9.3 数据结构建议

新增或补充以下实体：

- `MarketSentimentSnapshot`
- `ThemeHeatRow`
- `StockPoolRow`
- `TradeSignal`
- `PortfolioAction`
- `DailyPlanReport`

## 10. 验收标准

满足以下条件即可认为迭代 01 完成：

1. 能读取本地样本数据或真实数据源，成功生成当日股票池。
2. 每个股票池条目都有分数、动作、买点、止损、目标位和解释。
3. 持仓列表能输出至少 HOLD / TRIM / EXIT 三类建议。
4. 生成一份盘前 Markdown 和一份盘后 Markdown。
5. UI 中可以直接查看市场情绪、股票池和持仓动作。
6. 所有交易动作都需要人工确认，不允许静默自动执行。

## 11. 已知风险

- A 股实时数据、资金流和新闻质量会直接影响建议质量。
- 没有题材热度引擎时，股票池容易偏“个股正确、方向错误”。
- 如果没有统一板块映射，热点识别会不稳定。
- AI 解读必须受规则结果约束，不能让自然语言反向改写规则。
