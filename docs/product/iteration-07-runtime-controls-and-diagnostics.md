# 迭代 07 - 运行控制与诊断闭环

## 目标

把“能运行”继续推进到“可观察、可导出、可维护”，让桌面端在长期使用、盘中刷新和问题排查时更稳、更透明。

## 本次迭代内容

### 1. 运行面板可操作化

- 在交易执行页新增 `刷新运行状态`、`导出运行日志`、`清理市场缓存` 三个操作按钮。
- 运行状态面板不再只做展示，而是具备即时维护能力，便于盘中快速排查。

### 2. 后台任务指标补全

- 为后台任务补充累计次数、成功次数、失败次数、最近任务状态、最近耗时等指标。
- 在任务开始、完成、失败、跳过重复执行时写入统一运行日志。

### 3. 缓存治理

- 为本地市场缓存增加 `clear()` 能力，支持一键清理缓存文件。
- 清理后在运行状态面板中展示本次清理结果，形成维护闭环。

### 4. 运维留痕

- 运行日志支持一键导出到本地 `exports/runtime` 目录。
- 导出文件包含运行概览和事件日志，便于留档、排查和复盘。

## 用户价值

- 盘中出现卡顿、数据异常或缓存脏读时，用户可以直接在界面里处理。
- 运行状态更透明，后台任务是否在执行、最近是否失败一眼可见。
- 问题发生后可以直接导出日志，不需要重复描述现场。

## 技术实现位置

- `app_qt.py`
  - 运行状态面板按钮接入
  - 后台任务耗时与成功/失败指标
  - 运行日志导出
- `quant_hunter/market_feed.py`
  - 本地市场缓存清理能力
- `tests/test_core.py`
  - 缓存清理回归测试
  - 解释器差异下的 UI / GM 运行时测试修正

## 验收标准

- 交易执行页可见运行面板操作按钮。
- 点击导出后可在 `exports/runtime` 下看到日志文件。
- 点击清理缓存后缓存文件数归零或按预期减少。
- 后台任务执行后，运行状态里能看到累计次数、成功/失败和最近任务耗时。

- 为缓存增加按类别清理和自动淘汰策略。
