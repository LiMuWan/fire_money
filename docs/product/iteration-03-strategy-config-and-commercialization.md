# 迭代 03 - 策略配置、关注题材与商业化骨架

## 目标

把“主线题材驱动”的交易流程继续产品化，让用户不只看到系统给出的结论，还能配置自己的交易边界、关注方向和授权状态。

本次迭代重点解决三件事：

- 策略阈值可配置，而不是写死在代码里。
- 用户可以定义关注题材，并在盘前计划与盘中监控里持续跟踪。
- 产品具备试用版 / 专业版的授权骨架，便于后续商业化。

## 用户价值

- 专业用户可以按自己的风险偏好设置“主线前 N、总仓位上限、题材掉队是否减仓”。
- 高频跟踪用户可以把精力聚焦在少数看好的主线题材上。
- 商业化团队可以在不破坏研究流程的前提下，为未来授权、试用期和功能分级预留接口。

## 范围

### 1. 配置页

- 新增“配置”页。
- 展示并保存以下策略参数：
  - 主线题材阈值 `top_theme_limit`
  - 总仓位上限 `max_total_exposure`
  - 题材掉队后是否优先减仓 `theme_drop_reduce`
  - 用户关注题材 `focus_themes`

### 2. 交易计划联动

- 盘前交易计划和持仓建议必须读取配置页中的实时参数。
- 交易计划文本中增加“关注题材”摘要。
- 导出的 Markdown / JSON 报告中记录当前策略参数对应的授权方案和关注题材。

### 3. 盘中监控联动

- 盘中监控摘要增加“关注题材命中数”。
- 当标的所属题材跌出主线阈值时，继续触发题材掉队提醒。
- 关注题材与掉队提醒要同时可见，避免只看到风险提示却不知道用户正在盯哪些方向。

### 4. 商业化骨架

- 本地状态中增加 `license_plan` 与 `trial_started_at`。
- 提供试用版 / 专业版的本地切换骨架。
- 配置页显示当前授权方案、试用开始日期、剩余试用天数。
- 当前版本不接远程授权服务，只保留本地骨架与 UI 状态。

## 实现方案

### 数据层

- `quant_hunter/storage.py`
  - 扩展 `AppState`，保存策略参数、关注题材、授权状态。

### 决策层

- `quant_hunter/decision.py`
  - `build_plan()` 支持从外部注入主线阈值、总仓位上限、题材掉队规则。

### 报告层

- `quant_hunter/reports.py`
  - `export_daily_trade_plan()` 和 `export_end_of_day_review()` 输出：
    - 授权方案
    - 用户关注题材

### UI 层

- `app_qt.py`
  - 新增配置页。
  - 保存配置后立即刷新推荐、交易计划和盘中监控。
  - 仪表盘标签同步新增“配置”页签。

## 验收标准

- 用户修改主线前 N 后，新的交易计划结果立即变化。
- 用户修改总仓位上限后，计划文本和导出报告显示新的上限。
- 用户设置关注题材后，盘前计划和盘中监控可见该信息。
- 导出的盘前计划 / 收盘复盘报告中包含 `license_plan` 和 `focus_themes`。
- 应用重启后，以上配置都能恢复。

## 商业化说明

- `TRIAL` 默认 14 天，当前阶段仅展示状态，不限制核心研究流程。
- `PRO` 作为专业版骨架，后续可绑定：
  - 更多数据源
  - 更深历史回放
  - 盘中自动监控
  - 机构级报表导出

## 风险与后续

- 本地授权状态不能替代正式商业授权，后续需要服务端签名或设备绑定。
- 关注题材目前仍依赖题材归因质量，后续应继续增强题材词典、新闻分类和事件抽取能力。
